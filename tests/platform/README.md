# Кроссплатформенные испытания BuildWheel

Эта инфраструктура существует только в test/platform-compatibility. Ветка содержит локальные исправления F-01/F-03; перед испытаниями SHA-256 runtime-файлов сравниваются с source-lock.json, привязанным к коммиту исправлений (исходный main:3ed6ea5). Workflow реагирует на push только этой ветки. Права GITHUB_TOKEN: contents:read; публикаций, merge и релизов в workflow нет.

Матрица: ubuntu-24.04 x64, macos-15-intel x64, macos-15 ARM64, TemurinJava25. Используется официальный Mindustryv160.7 JAR; SHA25636d94941a1639478ad1d9be25a9d802c6f77552f400c6da0338b7b019f63a0d1 проверяется до исполнения. Нативные библиотеки берутся из него штатным загрузчиком Arc. Дополнительный Linux-сценарий проверяет системную SDL, отключая предварительное извлечение libSDL2.so через предусмотренный Arc флаг SDL2_STATIC. Название этого флага не означает, что мод пересобирается статически.

## Уровни проверки

1. StartupHarness: настоящий JVM целевой ОС, Rhino и Arc-виджеты, весь граф текущих JS-модулей. Графика/аудио/окно/контент имитированы. Проверяются заводская загрузка EN/RU, регистрация обработчиков, UI, отсутствие FFM при загрузке и сохранённом relativeMouse=true. Пользовательские и повреждённые Settings читаются повторно в новом JVM без заполнения заново. Проверяются независимые значения по умолчанию, корректные соседние и скрытые слоты, точные исходные типы Settings и неизменные байты существующей библиотеки. ClassCastException теперь всегда провал проверки.
2. NativeProbe: настоящее окно/GL/SDL/FFM и текущий sdl-relative.js. Backend-only не исполняет адаптер и не меняет relative mode. Normal проверяет подтверждение образа/GL-окна, warp, чужой режим,3 цикла begin/sample/end, resize, minimize/focus, dispose, курсор и память. Forced-warp должен безопасно отказываться. Linux automatic-warp использует отдельную настоящую SDL2.0.10, собранную с --disable-video-x11-xinput: при hint=false прямой SDL setter обязан принять fallback, а BuildWheel — отказать до захвата, сохранив обычный warp. Архив SDL и загруженный файл имеют собственные контрольные суммы; эта сборка не подменяет проверки штатной SDL игры.
3. GameSmoke: запускает настоящий DesktopLauncher и копию неизменённого мода в новом профиле. После реального ClientLoad находит зарегистрированный пункт меню, открывает Радиальное меню и рисует его не менее3 кадров/3 секунд. Сохраняет screenshot и ждёт штатного освобождения приложения. Графика, загрузчик модов/скриптов и контент здесь не имитированы. Это проверка загрузки и редактора, не всего игрового процесса/строительства.

Для Wayland дополнительно есть отдельный raw-SDL компонентный сценарий. Он создаёт настоящее SDL-окно/GL-контекст, обрабатывает настоящую очередь SDL и исполняет неизменённый адаптер через FFM, но использует фасад размеров Core.graphics и отдельный Application вместо SdlApplication. Это позволяет исследовать SDL/FFM при обнаруженной ошибке штатного Arc GLEW. Сам Arc и игра таким способом не исправляются; успешный raw-SDL тест не считается совместимостью Mindustry с Wayland.

## Графическая среда

Linux: Xvfb + Openbox + Mesa llvmpipe. Wayland отдельно запускается в Weston X11 backend с настоящим input seat. XTest/xdotool передаёт движения через настоящий X-сервер и, для Wayland, через настоящий compositor/protocol. Это синтетический источник, а не физическая мышь.

macOS: используется графический сеанс runner и -XstartOnFirstThread. Pointer.swift проверяет CGPreflightPostEventAccess, активирует только процесс пробного приложения и при разрешении отправляет CoreGraphics HID events. TCC не изменяется. Нет разрешения/GUI/дельт — ограничение или безопасный отказ, не доказательство работающего ввода.

## Запуск

Workflow: .github/workflows/platform-compatibility.yml. Каждый push тестовой инфраструктуры в разрешённую ветку запускает матрицу. workflow_dispatch добавлен для будущего ручного запуска; GitHub может требовать наличие workflow в defaultbranch, поэтому основной способ здесь — push тестовой ветки. Main для этого не меняется.

Ручной запуск на Linux/macOS с JDK25 и зависимостями из workflow:

    python3 tests/platform/run.py --output /absolute/disposable/directory

Все настройки, сохранения, временные библиотеки и crashlogs помещаются в указанный каталог. Runner не открывает профиль установленной игры. GameSmoke получает отдельную копию mod.hjson/scripts/bundles/sprites/sounds.

## Интерпретация

- COMPONENT_* — успешное исполнение конкретных нативных компонентов, с указанными ограничениями.
- FULL_GAME_CLIENTLOAD_EDITOR_RENDERED — настоящий клиент/мод/редактор отрисованы и штатно закрыты.
- SAFE_REFUSAL_* — адаптер безопасно отказал; relative mode не сертифицирован.
- INFRASTRUCTURE_* / GAME_OR_INFRASTRUCTURE_FAILURE — нужна причина из журналов; не приписывать автоматически моду.
- CONFIRMED_COMPONENT_DEFECT — конкретная проверка адаптера нарушена; учитывать контекст forced-warp и способ генерации событий.
- PASS_RECOVERY_AND_PRESERVATION — загрузка пережила повреждённые поля, сохранность Settings и библиотеки проверена; графика остаётся имитацией.
- INCONCLUSIVE_NO_OBSERVED_MOTION — движение не наблюдалось; отсутствие мыши/разрешения не превращается в pass.

Результаты, команды, версии, адреса/образы библиотек, SDLerror, JSONL этапы, screenshots и hs_err сохраняются как GitHub Actions artifacts14 дней. Полный игровой JAR и дерево сборки тестовой SDL в артефакт не загружаются. Зелёный job не равен сертификации всей платформы. Повреждённые настройки и fallback не исключены из критериев ошибки. Отдельные известные отказы штатного Wayland/GLEW сохраняются и могут оставить Linux job красным.

Нет испытаний физического устройства, всех compositor/GPU, полного строительства, multiplayer или всех сочетаний других модов.

## Граница доказательства F-03

Linux использует только публичные SDL_SysWMinfo и XIGetSelectedEvents собственного XDisplay SDL. В исследованных X11 backend SDL2.0.10,2.30.0,2.32.8 подписка XIAllMasterDevices/XI_RawMotion устанавливается после успешной инициализации XInput2; setter затем принимает настоящий режим именно при этой инициализации. Сопоставление библиотек выполняется до нативных вызовов. Проверка подписки однократная; hint и SDL error проверяются при включении, обработка движения не усложнена.

Это не универсальный getter внутреннего warp-флага. Неизвестные SDL и backend без публичного подтверждения безопасно отказывают только в относительном вводе. Доказательство не охватывает произвольно изменённые vendor-сборки с тем же номером версии или другой мод, меняющий подписки на том же XDisplay. Реальные устройства и их ускорение этим не сертифицируются.

Исходники: [SDL XInput2 2.0.10](https://github.com/libsdl-org/SDL/blob/release-2.0.10/src/video/x11/SDL_x11xinput2.c#L116), [X11 setter](https://github.com/libsdl-org/SDL/blob/release-2.0.10/src/video/x11/SDL_x11mouse.c#L335), [fallback](https://github.com/libsdl-org/SDL/blob/release-2.0.10/src/events/SDL_mouse.c#L931), [публичный контракт XIGetSelectedEvents](https://xorg.freedesktop.org/archive/X11R7.5/doc/man/man3/XISelectEvents.3.html).

## Локальный Windows

WindowsNativeProbe наследует только общие диагностические функции. Его CLI совпадает с NativeProbe; поддерживаются normal и forced-warp. Работают настоящие Arc/SDL/FFM, три цикла, обычный warp и освобождение. Инъекция user32 mouse_event разрешена только при принадлежности переднего окна процессу; начальные координаты возвращаются после освобождения. Состояние SDL mode подтверждено внутренними проверками самого адаптера, отдельного неподтверждённого поиска адресов в тесте нет. -Dbuildwheel.probe.inject=false выключает инъекцию. Запускать с явным временным каталогом и внешним тайм-аутом, отдельно от пользовательской игры.
